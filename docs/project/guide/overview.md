# nove 项目概述

> **本文档是项目概述。** 需求与场景、目标与指标、组织与运营已拆分到独立文档：
> [需求与范围](./requirements) · [目标与成功指标](./goals) · [组织与运营](./organization)

## 一、项目概述

nove 致力于构建一个**组织级 Agent 数据基础设施（数据网关）** —— 让组织数据成为 AI 与 Agent 可以安全调用的资产。

系统通过 **严格的人机权限控制 + 实时/定时多源数据汇聚 + AI 实时预处理 + 多协议对外接口**，让组织散落在各处的数据（会议、订单、用户、聊天、邮件、合同……）汇聚成**庞大而有机结合的数据资产**，供 AI、Agent 与人类按需使用。

项目的第一个落地客户为 **陆向谦实验室**（教育场景）。在完成实验室级验证后，平台将逐步拓展至：

- 专业教育机构
- 高等院校
- 企业培训与组织学习
- 泛教育与知识服务型组织
- 更广泛的中小企业数据管理场景（个人市场不在 v1 范围）

最终目标是构建一个可横向复制、纵向深化的 **新一代智能数据基础设施**。

---

## 二、项目愿景与核心理念

### 项目愿景

> **让每个组织的数据，都能被 AI 理解、关联与复用。**

nove 不只是一个数据存储工具，而是一个**让组织数据持续增值、可被 AI 安全调用的数据基础设施** —— 数据进来时是孤立的记录，经过 nove 后成为有机联系的知识资产。

### 核心理念

- **权限为本**：对 AI 的访问实行严格、全面、可审计的权限控制
- **数据汇聚**：把散落在会议、订单、聊天、邮件、合同等系统中的数据实时/定时汇聚到一个仓库
- **AI 关联**：AI 自动找出数据间的关联与联系，形成组织级别的"有机结合的数据资产"
- **Agent 优先**：数据的主要消费者是 AI 与 Agent，人类通过 nove-admin 查看与操作

---

## 三、系统定位

**组织级 · Agent 数据基础设施（数据网关）**

nove 的系统定位是：

- **组织级数据基础设施**：统一承载组织多源业务数据，v1 聚焦组织场景
- **面向 AI 与 Agent**：通过 API、MCP、Skill、CLI 等接口对外提供数据交互
- **权限为本**：AI 以独立身份接入，最小授权、全量审计，只能在授权范围内访问数据
- **人类入口为 nove-admin**：查看与操作走管理后台
- **可配置、可扩展、可复用**：内置数据仓库格式，支持自定义方式接入新数据形态

---

## 四、核心特点

### 1. 严格的人机权限控制

- 对 AI 实行严格、全面的权限访问控制
- AI 以独立身份接入，最小授权、全量审计
- 这是 nove 的第一差异化能力：让组织"放心把数据交给 Agent 用"

### 2. 多协议对外接口

- API、MCP、Skill、CLI 等一系列接口对外提供数据交互
- 可嵌入任何 Agent Harness 与 Agent 应用平台，作为组织数据的开放网关

### 3. 多源数据汇聚与业务资产全景

- 实时、定时从多维业务系统汇聚数据：
  - **协作与会议**：腾讯会议（`tmeet`）、飞书会议（`lark`）、企业微信（`wecom`）；
  - **交易与激励**：Stripe 国际化支付与结算、微信小店（`wechat-shop`）、商业订单/退款、自动分润与退款冲销追回、月度工资条；
  - **组织与项目**：组织成员与实名证件、跨平台用户映射、项目与课程规划；
  - **数字资产**：统一云盘存储中心（`drive`），支持与商品媒体、项目封面资产强绑定归档；
  - 聊天记录、客户对接、合同等为规划中数据源（详见 [数据源接入矩阵](./data-sources)）。
- 数据接入能力通过中心化集成管理持续扩展，内置连通性健康自测。

### 4. 三大业务数据资产飞轮

nove 在组织内部驱动三大相互交织的数据资产飞轮：
1. **协作与知识资产飞轮**：会议录制与转写 → AI 提取结构化转写与发言人观点总结 → 周期跟踪报告 → 沉淀为 Agent 可精准检索的组织记忆。
2. **商业交易与激励飞轮**：商品管理与支付接入（Stripe / 微信小店） → 订单权益天数计算与调整 → 多维度自动化分润摊销 → 全局退款冲销追回引擎 → 成员工资条生成。
3. **组织协同与数字资产飞轮**：组织架构与企微通讯录同步 → 跨平台账号聚合与实名凭据审核 → 项目与课程推进 → 云盘数字资产归档沉淀。

### 5. AI 实时预处理

- 数据入库后由 AI 实时预处理（如自动对用户的参会记录进行发言总结与结构化转写）
- 自动提取数据间的核心实体，为后续跨域关联与知识图谱构建奠定基础

### 6. 可拓展的数据格式

- 内置标准化数据仓库格式（Prisma 7 模块化架构定义 44 个核心模型）
- 支持通过自定义方式（插件或其他形式）接入新的数据形式
- 现状与设计取向探讨见 [数据格式与扩展机制（方案探讨）](/project/architecture/data-format)

## 五、AI 能力归属（架构决策）

> ⚠️ **现状说明**：nove-ai（FastAPI）目前处于**规划中（仓库尚未实现）**。当前实际可用的 AI 能力由 nove-api 内嵌 LlmService（OpenAI 兼容接口）承担轻量调用（会议摘要、跟踪报告汇总等）；下表为既定架构方向，重量能力（关联发现、图谱、画像）随 nove-ai 落地。整体能力状态见 [能力状态总览](./capabilities)。

nove 的 AI 能力采用**轻/重分层**，实体归属 **nove-ai（FastAPI + Python）**：

| 任务类型 | 示例 | 归属 |
|---|---|---|
| 轻量同步 | 实体抽取、字段映射、短文本分类、单场会议摘要 | nove-api 内嵌封装（AiClient） |
| 重量异步 | Embedding 入库、语义关联发现、知识图谱构建、批量转写总结、用户画像 | 现阶段优先由外部 Agent 代办；远期归属 nove-ai（Python），Job 化 |

- nove-api 永不直接依赖具体模型，只通过 AiClient（超时/重试/熔断/降级）调用
- 服务间用 HMAC 签名鉴权（方案详见 [技术方案总览](/project/architecture/overview) 第七节）
- 慢任务一律异步 Job（queued → running → succeeded / failed），结果回写数据库

## 六、技术实现方向（概览）

- 前端：nove-admin（React + Vite + Ant Design，人类工作台，涵盖 16 大业务与管理模块）
- 后端：nove-api（NestJS + TypeScript + Prisma 7，多源数据接入 / 组织多租户隔离 / 商业结算 / 资产驱动 / 权限 / API 暴露）
- CLI 客户端：nove-cli（oclif，v1.3.0 覆盖 8 大业务域，支持浏览器 OAuth 授权登录）
- AI 层：nove-ai（FastAPI + Python，预处理 / 关联 / 图谱 / 画像，**规划中**；当前轻量 AI 由 nove-api 内嵌 LlmService 承担）
- 数据层：PostgreSQL（Prisma 7 驱动适配器，44 个模块化子模型） + Redis + Drive 云盘存储（+ 向量库规划中）
- 接口层：RESTful API / GraphQL / MCP Server / Agent Skill / CLI
- 架构原则：**可扩展、可演进、可持续、权限为本**

## 七、实施路径与扩展路线

### 实施阶段

1. **阶段一：数据汇聚 MVP**
   - 核心数据源接入（会议、订单、用户）
   - 基础 AI 预处理（自动总结、字段映射）
   - 基础数据结构与权限模型

2. **阶段二：接口与智能**
   - API / MCP / Skill / CLI 全面开放
   - AI 关联发现与语义层
   - 严格的人机权限与审计体系

3. **阶段三：平台化**
   - 插件化数据接入
   - 多租户与横向复制
   - 作为通用 Agent 数据基础设施对外服务

### 扩展路径

陆向谦实验室（教育场景，v1 样板）\
→ 教育机构 / 高校 / 企业培训 / 知识服务型组织\
→ 更广泛的中小企业数据管理场景（个人市场不在 v1 范围）

> 注：教育平台是 nove 能力的一个应用场景，不是定位本身；nove 的定位是组织级 Agent 数据基础设施（数据网关），v1 聚焦组织场景。

## 八、历史沿革

- v1.0（2025-09）："实验室 AI 智脑与教育中台"版本，以陆向谦实验室教育场景为切入点。
- v2.0：定位收敛为"个人 / 组织 / 企业数据仓库与 Agent 数据基础设施"，教育场景作为首个落地用例保留。
- v2.1（当前）：主词进一步收敛为"组织级 Agent 数据基础设施（数据网关）"，人机权限与全量审计提为第一差异化；明确个人市场不在 v1 范围。

## 九、术语

- 数据仓库（Data Warehouse）：统一汇聚、存储组织多源数据的系统。
- 人机统一权限：人类用户与 AI Agent 均作为独立访问主体的权限体系。
- MCP：Model Context Protocol，模型上下文协议，供 LLM / Agent 调用数据与工具。
- Skill：面向 Agent 的技能化接口封装（如 nove-skills）。
- RAG：Retrieval-Augmented Generation，检索增强生成。
- HMAC：Hash-based Message Authentication Code，服务间请求签名鉴权。

## 十、总结

nove 并非只是"又一个数据库"，\
而是 **AI 时代组织数据的基础设施**：

- 从"数据存储" → "数据关联与增值"
- 从"人类专用" → "人机共用、Agent 优先"
- 从"单一系统" → "API / MCP / Skill / CLI 多协议开放"

**让每一个组织的数据，都成为 AI 可以安全、按权限调用的资产。**

# nove · 三年技术与 AI 演进路线图
**（2026 – 2028）**

> 本路线图用于指导 nove 从「组织级 Agent 数据基础设施（数据网关）」成长为「可规模化复制的智能数据基础设施」，覆盖 **系统架构、AI 能力、数据治理与工程成熟度** 四个维度。

---

## 一、总体演进理念

### 1. 核心判断

- **数据是长周期资产**：技术必须稳定、可演进
- **AI 是能力，不是噱头**：先决策，后生成
- **权限是底线**：AI 访问数据必须受控、可审计
- **工程治理决定上限**：可维护性 > 短期效率

### 2. 三年技术主线

> **第 1 年跑通数据汇聚闭环**\
> **第 2 年形成数据平台**\
> **第 3 年构建智能壁垒**

---

## 二、第一阶段（Year 1）：验证与闭环
### 时间范围：第 0–12 个月
### 技术关键词：**MVP / 多源接入 / 单租户 → 准多租户**

### 2.1 目标定位
- 服务首发客户（陆向谦实验室，教育场景）
- 跑通"多源数据 → 入库 → AI 预处理 → 关联 → 接口调用"完整闭环
- 证明"组织数据仓库"在真实组织内可落地

### 2.2 系统架构演进

- 架构：
  - nove-admin（React，人类入口）
  - nove-api（NestJS，数据仓库主服务）
  - 外部 Agent 软件（如 OpenClaw / Hermes，前期代办复杂 AI 计算，远期演进为自研 nove-ai）
- 部署：
  - Docker Compose
  - 单环境（prod / staging）

### 2.3 AI 能力演进（重点）

**核心能力**
- 数据预处理（自动总结 / 实体抽取 / 字段映射）
- 跨源关联发现（Embedding + 规则混合）
- 批量转写总结与画像

**设计原则**
- 结构化输出
- 强可解释性
- 轻量任务（同步）留在 nove-api，重量任务（异步 Job）交由外部 Agent 软件（远期归 nove-ai）

> ❌ 不做：无约束的开放式数据访问\
> ✅ 做：受控、可审计的 AI 数据调用

### 2.4 数据与治理

- PostgreSQL：业务 + AI 结果快照
- Redis：任务 / 缓存
- 明确数据责任边界：
  - nove-api：事实数据（业务真相）
  - AI 计算层（外部 Agent / 远期 nove-ai）：计算结果（可重建）
- 内置数据仓库格式 + 元数据 / 溯源

### 2.5 成功标志（Year 1 Exit）

- 核心数据源（会议 / 订单 / 用户）100% 接入
- ≥ 3 个外部 Agent 通过 API / MCP / Skill 稳定调用
- AI 服务宕机 ≠ 数据仓库不可用

---

## 三、第二阶段（Year 2）：平台化与复制
### 时间范围：第 13–24 个月
### 技术关键词：**多租户 / 插件化 / AI 编排**

### 3.1 目标定位

- 从"服务一个组织" → "服务多组织"
- 插件化数据接入（新数据源 / 新数据格式）
- 建立可复用的 AI 能力模块

### 3.2 架构演进

- 引入 **多租户模型（Tenant）**
- nove-api：
  - 拆分领域模块
  - 部分服务可独立部署
- AI 计算侧：
  - 逐步启动自研 nove-ai 服务，平滑替代前期过渡使用的外部 Agent 软件
  - AI 能力模块化（Preprocess / Link / Embed / Profile）

### 3.3 AI 能力演进

**新增能力**
- 长期组织画像（跨系统 / 跨周期）
- 数据关联图谱动态更新
- 智能体编排（按场景封装数据访问）

**技术升级**
- 引入向量检索（pgvector / Milvus）
- 小模型 + 规则混合决策
- Prompt 与模型版本治理

### 3.4 数据与隐私

- 数据隔离（Tenant 级）
- AI 访问全量审计报告
- 支持对外合规说明（组织 / 机构）

### 3.5 成功标志（Year 2 Exit）

- 新组织接入成本显著降低（插件化接入 ≤ 2 小时）
- AI 能力不依赖单一模型
- nove 成为"组织数据基础设施"

---

## 四、第三阶段（Year 3）：智能壁垒与生态
### 时间范围：第 25–36 个月
### 技术关键词：**智能中枢 / 预测能力 / 生态开放**

### 4.1 目标定位

- nove 从"数据平台"升级为"组织智能数据中枢"
- AI 具备预测与策略能力（基于关联图谱）
- 支撑规模化、生态化扩展

### 4.2 架构演进

- 完整云原生（Kubernetes）
- AI 服务支持 GPU / 弹性调度
- 引入事件驱动架构（Event-driven）

### 4.3 AI 能力跃迁（核心壁垒）

**高级能力**
- 组织风险预测（客户流失 / 项目停滞 / 协作断裂）
- 数据驱动的策略推荐
- 组织知识网络建模（人 / 事 / 项目 / 客户全息关联）

**能力形态**
- AI 从"响应式" → "预测式"
- 从"查询" → "策略模拟"

### 4.4 平台与生态

- 数据与 AI 能力对外 API（受控）
- 支持教育机构 / 高校 / 企业培训 / 中小企业
- nove 成为 Agent 时代的数据基础设施提供方

### 4.5 成功标志（Year 3 Exit）

- AI 关联能力成为核心竞争壁垒
- 组织难以自行复制 nove 能力
- 技术体系可支撑规模化扩张

---

## 五、三年路线图总结

| 维度 | Year 1 | Year 2 | Year 3 |
|----|----|----|----|
| 客户 | 单组织（实验室） | 多组织 | 行业级 |
| 架构 | 模块化单体 | 平台化 / 插件化 | 云原生 |
| AI | 预处理辅助 | 关联编排 | 预测中枢 |
| 权限 | 人机统一 | 多租户审计 | 生态级治理 |
| 目标 | 跑通 | 复制 | 壁垒 |

---

## 六、结语

> **真正的数据基础设施，不是"存了很多数据"，\
> 而是"让 AI 能安全、按权限地理解与使用组织的数据"。**

nove 的三年技术路线，正是围绕这一信念展开。
